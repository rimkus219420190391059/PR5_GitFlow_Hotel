# Чек-лист Code Review

Для слияния в `develop` необходимы не менее двух одобрений участников команды и финальное утверждение Tech Lead.

## Архитектура
- [ ] Соблюдены границы Clean Architecture.
- [ ] Core не зависит от Infrastructure или WebApi.
- [ ] Бизнес-логика не размещена в контроллерах.

## Безопасность и валидация
- [ ] Проверяются входные данные СКУД и авторизации.
- [ ] Защищённые конечные точки используют `[Authorize(Roles = "...")]`, где требуется.
- [ ] Регулярные выражения проверены на риск ReDoS.
- [ ] Секреты не добавлены в репозиторий.

## Надёжность
- [ ] Обрабатываются тайм-ауты СКУД и сбои платёжного шлюза.
- [ ] Для временных ошибок предусмотрена обоснованная Retry Policy (например, Polly).
- [ ] Повторные запросы не создают дублирующие операции.

## Качество кода
- [ ] Соблюдаются соглашения C#/.NET.
- [ ] Имена понятны, магические значения и ненужный хардкод отсутствуют.
- [ ] Нет неиспользуемого или дублирующегося кода.

## Тесты
- [ ] Добавлены unit-тесты новой логики.
- [ ] Добавлены integration-тесты для изменённых взаимодействий.
- [ ] Проверены негативные сценарии и граничные значения.
- [ ] Все тесты проходят.

## Ресурсы и БД
- [ ] `HttpClient`, `DbContext` и другие ресурсы используются корректно.
- [ ] Асинхронные операции и освобождение ресурсов безопасны.
- [ ] Запросы EF Core не создают проблемы N+1.
- [ ] Изменения БД сопровождаются миграциями.

## Решение
- [ ] CI завершился успешно.
- [ ] Все замечания закрыты.
- [ ] Получены минимум два одобрения участников.
- [ ] Получено финальное одобрение Tech Lead.

После выполнения условий Tech Lead разрешает Squash and Merge в `develop`.
